My solution of Luogu P11361 [NOIP2024] Mutating Strings.

Original: Chinese

Translation: Gemini

Idea:

Consider a greedy approach.

The problem states that certain adjacent positions can be swapped. It is easy to see that within these large swappable "blocks" (i.e., an interval such that ), the characters can be sorted arbitrarily. That is, we can achieve any permutation of these characters through a finite number of adjacent swaps.

Therefore, we can first pre-process and identify these "blocks."

Then, we naturally iterate from left to right. If the characters match, we just match them. If they do not match, we check whether there is a character within the same block that can be brought to the current position to form a match. If such a character exists, we perform a swap; otherwise, we just give up on this position, meaning it cannot be matched.

So, how do we maintain the characters available for matching within a block? We can notice that during the iteration, the position of the first available character that can form a match is monotonically non-decreasing (because once a swap is made, the next available position must be strictly after it). Thus, we can use a two-pointer approach!

We maintain a primary pointer representing the current position under consideration. In addition, we maintain auxiliary pointers , which respectively represent the first position after that:

  • Makes the character in the first string at this position .
  • Makes the character in the first string at this position .
  • Makes the character in the second string at this position .
  • Makes the character in the second string at this position .

In each step, if , we simply skip it. Otherwise, we check whether these four pointers belong to the same block as . If they are not in the same block, it's impossible; if they are, we still need to verify whether they can form a match after the swap.

And then we are done :)
