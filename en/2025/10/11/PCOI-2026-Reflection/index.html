  • mins: AC T1.

A very classic problem. First glance, I knew it was a Binary Search (For Answer), since there aren't obvious other ways to solve the problem. Obviously you should do all the operations before the tree starts decaying. So how to check if there exists a way to save all the trees until day ? Firstly, I calculated the minimum operations needed (how many needed) for every tree to be alive for days. Then every operation means subtracting to the same segment in the minimum-operations-needed array. In the end you want every tree to have the needed minimum operations needed, hence the final array should have all values . So the problem becomes a much easier one:

Given an array, is it possible to use operations, every operation you can choose any segment with length , and subtract to all elements, such that after all operations, every element is ?

The rest is easy. You can Greedy. Scan the array from left to right, and when you see a element on index still , then make operation from to . Then becomes . Lastly, just check if the needed number of operations exceeds or not.

You can use Segment Tree to maintain the operations, or, be smarter, and just use Differences Array. After getting the Differences Array of the initial array, You need to maintain the actual value of (to see if it is ), and to make an operation, you just need to do a[i] -= a[i], a[i + k] += a[i], and you are done.

So I submit, and get WA. After staring at the code for mins, I found out that it might overflow long long. So I use __int128, and as I am lazy to write __int128 input, so I use long long for input and cast it to __int128. AC. Nice, but didn't get first kill because of this mistake. Sad.

  • mins: AC T3.

A really fun problem, as I tried to apply the same methods to Dino Game before.

I first tried to get the number when in . Well, after calculating the messy maths for about minutes, I got it. But I didn't pass Subtask . After debugging, thinking, and simulating, I figured out I didn't check the case when nothing needs to be moved, so I added an if statement, and successfully passed Subtask .

I knew that this calculation is really crucial (since it is very hard). I had a feeling that the rest is going to be easy, and it was.

Why the same solution doesn't work for segments? Well, it is because some segments might affect others. So I scan the whole thing from left to right, and maintain the minimum index of where the first cactus in every segment should be placed. So to move the segment , if the previous segments overflow, then just move it to where is the number so that previous segments and the current segment doesn't overlap. And calculate the number according to the new segment, and you are done. First kill, baby.

After ACing this problem I literally thought I was on AK pace (half the time, ACed half the problems, I guess). Turns out I was wrong. And that's when I start to mess up.

  • mins: Attempt T2 Full

I mistakenly thought T2 was easier than T4. Big mistake. T2 does look very tempting - the algorithms used are not that hard. However, I significantly underestimated the implementation difficulty of this problem.

Firstly, I offsetted the indexes to make sure they line up together. Then, I figured out that I just needed to do the following in each query:

  • See how far it can go using only interchanges.

After that, it will arrive at the first of a certain train line's interchangable stations. Then, I:

  • See how far it can go, until it can't go forward or arrives at the destination.

The first part can be done using a Sparse Table and Binary Search. Then the second part I preprocess the whole thing. I make a tree-like object, which stores which indexes can go where. Then I can run Binary DP (the thing that is also used in the implementation of Sparse Table) on the tree, so I can see how far it can go in .

So is the problem done? No! After mins of thinking + writing, I figured that the whole thing was too shitty to write (at least my solution is too shitty). Also, before the competition, I set a timeout for myself: If after mins into the problem and I don't know what I'm doing, then skip.
